# Experimental Design
## Experiment Strategy
Global Goal: Provide multi-angle evidence that COCO-BOIL is (1) faster in wall-clock time, (2) at least as sample-efficient, (3) more accurate/calibrated in cost prediction, (4) robust across tasks, budgets and seeds, and (5) practically lightweight.

1. Validation Aspects
   a. Wall-clock performance: time-to-reach-target, time-AUC, anytime curves.
   b. Sample efficiency: best objective vs. #finished trials.
   c. Cost surrogate quality: MAPE, RMSE, calibration error, uncertainty–quality (sharpness vs. coverage).
   d. Computational overhead: per-BO step latency, GPU/CPU utilisation, memory footprint.
   e. Robustness & generalisation: variance across random seeds, unseen tasks, hyper-parameter space size, regime change scenarios.

2. Comparative Grid (applied to every benchmark)
   • Strong baselines: original BOIL, Hyperband, CM-TF-BO, random search.
   • Ablations: (i) BOIL + MLP (M1 only), (ii) BOIL + MC expectation (M2 only), (iii) COCO-BOIL w/o dropout, (iv) COCO-BOIL full.
   • State-of-the-art extras (optional): MOBster, DEHB, SMAC3-HB.
   All runs share identical search spaces, training code and resource limits.

3. Experimental Angles
   a. Quantitative performance: median + 25/75th percentile curves over ≥20 seeds; statistical tests (Friedman / Wilcoxon signed-rank) on (i) time-to-threshold and (ii) AUC metrics.
   b. Qualitative analysis: visual learning-curve snapshots, cost-surface heat-maps, calibration plots (prediction vs. actual cost quantiles).
   c. Efficiency analysis: micro-benchmarking the extra Python lines (nsight-systems for GPU, cProfile for CPU).
   d. Stress tests: artificially inject cost regime changes (e.g., switch from FP32 to BF16 at given LR) to verify model adaptivity.

4. Demonstrating Effectiveness from Multiple Perspectives
   • End-user perspective: show fixed-budget results (e.g., 1-h GPU budget) – COCO-BOIL obtains higher reward/accuracy.
   • Practitioner perspective: show wall-clock gains at equal objective level (e.g., 95% CartPole success reached 30% sooner).
   • Researcher perspective: dissect why – lower MAPE → better acquisition → fewer high-cost mistakes.

5. Success Criteria (per task, aggregated across tasks)
   Primary: Median wall-clock to target reduced by ≥20% vs. BOIL with p<0.05.
   Secondary: Cost-prediction MAPE ≤10% and calibration error ≤0.05.
   Tertiary: Added per-iteration overhead <3% of total BO step time and GPU memory delta <200 MB.
   Robustness: Variance increase ≤5% relative to BOIL; no catastrophic failures (worst-seed slower than BOIL by >10%).
   Generalisation: On unseen tasks COCO-BOIL keeps ≥75% of the average speed-up seen on design tasks.

6. Practical Execution Plan
   • Hardware: assign 1 × A100 per optimisation run; runs parallelised across 256 logical cores/2 TB RAM server via SLURM.
   • Reproducibility: fixed Conda env, deterministic torch, unified logging (Weights & Biases), commit hash recording.
   • Budget: cap each run at 8 h; with 6 tasks × 8 methods × 20 seeds ≈ 960 GPU-hours (<2 days on 24 GPUs).
   • Data handling: central SQLite for (x,t,c) tuples enabling post-hoc surrogate evaluation without rerunning models.

7. Reporting Template (common across papers/appendices)
   • Table 1: time-to-threshold (%) ↓ ; AUC ↑ ; sample count ↓.
   • Table 2: MAPE, RMSE, calibration; overhead (ms).
   • Fig 1: anytime curves with confidence ribbon.
   • Fig 2: reliability diagrams.
   • Fig 3: ablation spider chart (normalised scores).

By applying this uniform, statistically-grounded strategy to all subsequent experiments, we ensure every claim about COCO-BOIL—speed, accuracy, robustness, lightness—is validated from complementary viewpoints and under realistic compute conditions on our A100/2 TB node.

# Current Experiment (To be validated)
- Experiment ID: exp-1
- Description: Objective / Hypothesis:
Main performance & robustness validation of the proposed COCO-BOIL against strong baselines and its own ablations.  We test whether COCO-BOIL reaches a target performance at least 20 % faster in wall-clock time while maintaining or improving sample-efficiency on all tasks.

Benchmarks & Models
• CartPole-v0 (Gym-Classic): Double-DQN (DDQN)
• InvertedPendulum-v2 (MuJoCo): Advantage Actor–Critic (A2C)
• Reacher-v2 (MuJoCo): A2C
• SVHN (vision): light CNN (conv-conv-fc) used in BOIL paper
• CIFAR-10 (vision): ResNet-18

Datasets & Pre-processing
• RL tasks: default Gym / MuJoCo environments, reward normalisation off, episode length capped at 500 steps.
• SVHN: 32×32 RGB, per-channel mean/σ normalisation.
• CIFAR-10: random 32×32 crop with 4-px padding, random horizontal flip, standard mean/σ normalisation.

Data Splits
• RL tasks: 90 % of episodes for training the agent inside each BO trial; 10 % held-out episodes used as validation reward that BO optimises.  Test reward reported once at the end.
• SVHN & CIFAR-10: train / validation / test = 45 k / 5 k / 10 k (standard split).

Search Space (same across variations)
• Learning-rate [1e-5, 3e-2] log-uniform
• Batch-size {32, 64, 128, 256}
• Network width multiplier {0.5, 1, 1.5}
• Dropout [0, 0.5]
• RL-specific: target-update period {100, 500, 1000}
Total dimensionality d = 7 (continuous + categorical one-hot).

Baselines & Variations
random-search              –  purely time-budgeted random sampling
BOIL-linear                 –  original BOIL with linear cost surrogate
COCO-BOIL-M1-only           –  linear surrogate replaced by 1-layer MLP, deterministic mean cost (tests M1)
COCO-BOIL-M2-only           –  linear surrogate + MC expectation (tests M2)
COCO-BOIL-full              –  MLP surrogate + stochastic expectation (M1+M2)

Repetitions & Averaging
• 20 independent seeds per (task × variation).  Seeds propagate to BO initialisation and model weight initialisation.
• Report median and inter-quartile range.  Statistical significance via Wilcoxon signed-rank on paired per-seed scores.
• The “best-val” policy: for each run we log validation metric every completed trial; wall-clock time is read from `time.perf_counter()`.

Evaluation Metrics
Primary
  – Time-to-reach-target (domain-specific threshold) ↓
  – Area-under-learning-curve (AULC) ↑
Secondary
  – # finished trials to target ↓
  – Cost-prediction MAPE, RMSE ↓
  – Expected Calibration Error (ECE) of cost surrogate ↓
  – FLOPs / GPU-hours / peak VRAM ↓
Robustness / Variance
  – Standard deviation of time-to-target across seeds and tasks ↓

Robustness Tests
1. Noise injection: add ±10 % Gaussian noise to reported training times online, measure impact on selection.
2. Distribution shift: at epoch 50 switch CNN training precision from FP32 to BF16 (induces regime change in cost).
3. Domain transfer: hold-out CIFAR-100 for post-hoc evaluation of learnt cost surrogate without retraining it.

Hyper-parameter Sensitivity
• Grid over MLP hidden size {4,8,16} and dropout {0.05,0.1,0.2}.  BO runs reused; surrogate retrained offline to quantify MAPE.

Compute Efficiency Logging
• Wrap each BO `suggest()` call with `torch.cuda.Event` timers; log Python wall-clock with `timeit`.
• Capture memory via `torch.cuda.max_memory_allocated()` and GPU util via `nvidia-smi --query-compute-apps`.

Expected Outcome
• COCO-BOIL-full reduces median time-to-target by ≥20 % on every task; average MAPE ≤10 % and ECE ≤0.05.
• Added per-iteration overhead <3 % wall-clock, <200 MB VRAM.
